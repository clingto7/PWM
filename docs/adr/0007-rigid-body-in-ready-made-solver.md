# 首轮不要求用户输入，车辆作为刚体交给现成求解器

首轮不给实时用户输入，只给车辆一个初速度或力，看现成物理求解器的解算是否正确。车辆建模为有质量、有摩擦、会碰撞的刚体。这取代了设计讨论第一轮里"运动学自行车模型"的暂定选择。

## Considered Options

- **刚体加现成求解器**（选定）。有质量、摩擦、碰撞和静止接触，给定初速度或力之后有东西可验：怎么滑、怎么撞、怎么停。转向驾驶等用户输入进来之后再做。
- **运动学自行车模型**（否决）。它是"给转向角和油门、算轨迹"的公式，没有质量和碰撞响应；没有用户输入时只能写死一段脚本，给定初速度后只会匀速直线走，看不出解算对不对。第一轮讨论中曾暂定用它，因首轮改为不需要用户输入而作废。
- **动力学自行车模型，含轮胎侧偏**（推迟）。参数标定的成本对首轮不值得。

求解器默认用 PyBullet，理由是 CPU 上能跑、支持高度图和凸包碰撞。这两点本次讨论没有核对到原始文档，开工时先确认，有更合适的再换。求解器位于"给定碰撞几何和车辆状态，输出下一时刻状态"这个接口后面，可以替换。

## Consequences

- 首轮的代理视频离线生成，不要求实时显示。
- "解算正确"的判据见 ADR-0008。
