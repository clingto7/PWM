# 跨图阶段从原图自动建场并在留出图片上验收

首轮原型只验证一张精选驾驶图，不能据此声称场景重建具有泛化能力。跨图阶段面向不同游戏的第三人称单张画面，要求图中有一个视觉上占主导的受控主体和可见的主要支撑面；顶层管线只接收原图，自动完成主体发现、分割、深度与网格生成，并保存中间结果以供诊断。运行时不使用 agent、LLM 或人工点击，不针对单张图片增补规则。

场景包含一个可有坡度和局部起伏的固定主要支撑面、一个受控的动态刚体，以及可可靠分离的主要静态实体；其余背景保留较粗几何。受控主体可为车辆、人物或机器人等不同外形，但本阶段均把整体视为一个刚体，不重建关节或车轮机构。主体的尺度和位姿拟合联合检查原视角轮廓、逐像素深度与支撑接触，并用无冲量物理试验诊断悬空和穿透。被遮挡后补全的表面须与观测表面区分记录。只开放由观测或充分连续性证据支持的区域供主体运动；无法可靠重建的区域成为交互边界，低置信疑似物体不直接转成实体碰撞。摩擦与恢复系数使用统一经验值，不在本阶段估计材质属性。

尺度拟合先保留不使用类别尺寸先验的基线。预先固定的类别尺寸先验只在视觉分类可信时作为弱约束使用，分类不明或与图像证据冲突时报告尺度不确定；有、无先验的结果分别记录为消融，不按图像手填实例尺寸。

泛化验收按游戏划分开发集和留出集，算法与参数在验收前冻结；少量人工标注只供验收，不进入运行管线。检测、几何、接触和渲染结果分别报告，符合输入条件的失败图片也计入。原图相机视角用于拟合和主要视觉验收，小范围新视角重渲染用于几何诊断；本阶段不要求任意方向漫游。逐图失败条件、各阶段指标、数值阈值与总体成功率要求须先在开发集上确定和审阅，再运行留出集；留出集结果不用于回调规则或阈值。此阶段不要求实时键盘控制或完整游戏玩法，以可重复动作序列检验交互。

实现阶段先用已有图片检查各阶段接口和可重放性；完整管线完成后再采集跨游戏样本。首批泛化试运行基准至少包含 3 款开发游戏与 3 款完全留出的游戏，每款至少 5 张不同场景的合格画面，覆盖不同主体外形。这是跨图故障调查的起点，不等同于“任意图片均可重建”的证明。
